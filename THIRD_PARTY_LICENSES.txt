2. CORE RUNTIME DISTRIBUTION (100% PERMISSIVE & ZERO EXTERNAL DEPENDENCIES - LEVEL 1 SBOM)
================================================================================
The base distribution wheel of accounts-core declares zero external runtime
dependencies (`dependencies = []` in pyproject.toml).
The entire core runtime execution relies strictly on the official Python
Standard Library under Python Software Foundation License 2.0 (PSFL-2.0).

| Component / Module      | Scope   | License  | Upstream Reference                    |
|-------------------------|---------|----------|---------------------------------------|
| Python Standard Library | Runtime | PSFL-2.0 | https://docs.python.org/3/license.html|
  Modules utilized: sqlite3, pathlib, typing, dataclasses, logging, os,
                    sys, re, datetime

All AccountStore CRUD operations, CAMT balance ingestion (camt.052, camt.053),
and allowlist-based transit projections execute purely using standard library modules.
Zero third-party telemetry, analytics, cloud storage, or remote networking
services are bundled, contacted, or initiated by the package (100% Local-First & Zero Egress).

4. ZERO-COPYLEFT BASE WHEEL & UNPRIVILEGED EXECUTION GUARANTEES
================================================================================
- Zero-Copyleft Core Guarantee: The core runtime package is 100% MIT-licensed
  with zero copyleft dependencies. Zero GPL, AGPL, or viral copyleft contamination.
- Unprivileged User-Mode Operation (RunAsInvoker): All operations, SQLite
  transactions, and snapshot publications execute purely within unprivileged user
  space. No administrative rights, root elevation, sudo, or UAC prompts are ever
  required or requested across Windows, Linux, or macOS.
- Immutable Source Database Isolation: Source SQLite databases are opened with
  explicit `mode=ro` during publishing; source, destination, and publisher
  checkpoint paths remain strictly distinct.

5. GOVERNANCE & RUNTIME INVARIANTS MATRIX
================================================================================
accounts-core strictly enforces ten foundational governance and runtime invariants:

| Invariant ID | Title                                 | Architectural Scope    | Compliance & License Guarantee |
|:-------------|:--------------------------------------|:-----------------------|:-------------------------------|
| INV-ACC-01   | Zero Database Ownership               | Schema Isolation       | Standard library sqlite3 only; operates on consumer table; 0 tables created. |
| INV-ACC-02   | Strict Allowlist Transit Projection   | Data Minimization      | Explicit 5-field projection (name, type, balance, date, iban_masked). |
| INV-ACC-03   | Masked IBAN Guarantee                 | Privacy by Design      | Bank IDs (BIC, bank, holder) excluded; IBAN masked to last 4 chars (****3000). |
| INV-ACC-04   | Pure Local-First & Zero Egress        | Network Perimeter      | Zero network calls, zero sockets, 100% offline stdlib execution in user space. |
| INV-ACC-05   | Immutable Source Isolation            | Concurrency & Safety   | Source DB opened with explicit mode=ro during transit publishing. |
| INV-ACC-06   | Atomic Snapshot Publishing            | Fault Tolerance        | Staged via temporary file and committed via atomic filesystem rename. |
| INV-ACC-07   | Idempotent CAMT Balance Ingestion     | Data Integrity         | Balances matched by normalized IBAN; returns German UTF-8 status reports. |
| INV-ACC-08   | Deterministic Fail-Closed Error       | Error Handling         | Typed standard library exceptions (FileNotFoundError, ValueError); no fallthrough. |
| INV-ACC-09   | RunAsInvoker Non-Elevation            | Execution Privilege    | Operates in unprivileged user space; zero admin elevation required. |
| INV-ACC-10   | 48h Security Response & 5-Day SLA     | Vulnerability Mgmt     | Formal 48h response and 5-day triage commitment documented in SECURITY.md. |
